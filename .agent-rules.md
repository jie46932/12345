# Agent Rules For This Project

## Router First

Before executing any project-specific task:

1. Read `PROJECT.md`.
2. Read `.agent-rules.md`.
3. Read the explicitly selected `.kiro/specs/<name>/` when the task has a Spec.
4. Read `F:\company-knowledge-base\web3d-nodes\router.md`.
5. Read `F:\company-knowledge-base\web3d-nodes\skill-router.json`.
6. Read `DOC/project-context.md`.
7. Read `DOC/node-overrides.json`.
8. Match the user task to one or more company routes.
9. Read the company node files listed in the matched route `readFirst`.
10. Apply project overrides and verified records before editing or validating.

If a global skill is unavailable, continue with the company node document and project overrides, then record the fallback in the task report.

Use `F:\company-knowledge-base\web3d-nodes\spec-driven-development.md` to decide Feature, Bugfix, Quick Plan or Skip. If no Spec is named, use the only Spec with unfinished tasks; when multiple candidates exist, ask for the Spec name instead of guessing.

## Verification

- Web/UI/3D changes require JavaScript verification, not screenshot-only evidence.
- For R3F/Three.js, verify canvas, resource loading, runtime globals, console errors, and user-path behavior.
- For deployment, verify Nginx, release symlink, MIME/cache, API health, and no sensitive files in release.
- Do not call `canvas.getContext()` on an existing R3F canvas just to verify WebGL; read runtime globals instead.

## Safety

- Do not upload source code, `.max`, `node_modules`, `.env`, `.git`, `_archive`, `DOC`, or temp archives to production.
- Do not upload `.kiro` or Spec Markdown to production.
- Do not write secrets into docs, frontend code, Git, or dist assets.
- Preserve user changes. Do not revert unrelated work.

## Project Runtime Boundary

- Use R3F/Three.js as the browser runtime.
- 3ds Max can still manually export glTF/bin/texture assets through Verge3D, but the web runtime must not depend on `v3d.js`.
